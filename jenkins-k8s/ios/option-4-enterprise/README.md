# iOS Enterprise Pipeline — Option 4

End-to-end Jenkins CI pipeline for an iOS enterprise banking app.
Works in two modes: **dummy signing** (no Apple account) for pipeline testing,
and **real enterprise signing** for production builds.

---

## Files

```
option-4-enterprise/
├── generate-dummy-signing.sh   # interactive signing setup tool
├── Jenkinsfile.groovy          # Jenkins pipeline
└── README.md                   # this file
```

Generated by the script (not committed):
```
dummy-signing/
├── ca.key / ca.crt             # self-signed root CA
├── dist.key / dist.crt         # iPhone Distribution leaf cert
├── dist.p12                    # PKCS#12 bundle
├── BankNow.mobileprovision     # CMS-signed fake enterprise profile
├── Entitlements.plist
├── ExportOptions-dummy.plist   # reference only
├── ExportOptions-enterprise.plist  # TEMPLATE for real org
└── signing-env.sh              # env vars sourced by Jenkins
```

## Quick Start

### 1. Prerequisites (Mac Mini, one-time)

```bash
# Xcode Command Line Tools
xcode-select --install

# Homebrew + openssl (macOS ships an old LibreSSL)
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
brew install openssl

# Node version manager (choose one)
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.7/install.sh | bash
nvm install 20 && nvm use 20

# pnpm (faster than npm in CI — see pnpm section below)
npm install -g pnpm

# CocoaPods
sudo gem install cocoapods
```

### 2. Run the signing setup tool

```bash
cd jenkins-k8s/ios/option-4-enterprise
chmod +x generate-dummy-signing.sh
./generate-dummy-signing.sh
```

An interactive menu appears — no flags to remember:

```
  ╔══════════════════════════════════════════════════════════╗
  ║     iOS Enterprise Signing Setup — macOS Tahoe (26)     ║
  ╚══════════════════════════════════════════════════════════╝

  Status
  ─────────────────────────────────────────────────────────
  ● Signing identity  : NOT found
  ● Generated files   : NOT found

  What would you like to do?

   1)  Generate dummy signing environment
   2)  Verify existing setup
   3)  Show signing identities
   4)  Show installed provisioning profiles
   5)  Clean up
   6)  Show / change configuration
   7)  Exit
```

Choose **1** to generate. The tool:
- Confirms your configuration before doing anything
- Creates a self-signed CA + iPhone Distribution cert
- Imports to a dedicated keychain with the Tahoe `set-key-partition-list` fix
- Creates a CMS-signed fake `.mobileprovision`
- Writes all plist files
- Shows a summary at the end

### 3. Run the Jenkins pipeline

In Jenkins, trigger **BankNow-iOS-Enterprise** with:
- `DUMMY_SIGNING = true` (uses what the script generated)
- `USE_PNPM = true`
- `ENVIRONMENT = Sit`

## Script Menu Reference

| Option | What it does |
|--------|-------------|
| 1 — Generate | Creates all certs, keychain, profiles, plists. Asks for confirmation first. |
| 2 — Verify | Checks every file and the keychain identity. Shows pass/fail per item. |
| 3 — Show identities | Lists `iPhone Distribution` certs in dummy and login keychains. |
| 4 — Show profiles | Lists all installed `.mobileprovision` files with name, UUID, expiry and colour-coded status. |
| 5 — Clean up | Removes keychain, output dir, and the installed profile. Asks for confirmation. |
| 6 — Configuration | Shows current values and explains how to change them. |

**Non-interactive flags** (for use inside Jenkins `sh` blocks):

```bash
./generate-dummy-signing.sh --generate    # generate (no prompts)
./generate-dummy-signing.sh --verify      # verify   (no prompts)
./generate-dummy-signing.sh --clean       # clean up (no prompts)
./generate-dummy-signing.sh --identities  # show certs
```

**Edit configuration** — open the script and change the block at the top:

```bash
TEAM_ID="DUMTEAM01"
TEAM_NAME="YourBank Ltd"
APP_NAME="BankNow"
BUNDLE_ID="com.yourbank.banknow"
CERT_VALIDITY_DAYS=365
KEYCHAIN_NAME="ios-banknow-dummy.keychain"
```

## Jenkins Setup

### Credentials to create (Manage Jenkins → Credentials → Global)

#### Dummy signing (not needed — script handles everything)

#### Real signing (`DUMMY_SIGNING=false`)

| ID | Type | Content |
|----|------|---------|
| `ios-enterprise-dist-cert-p12` | Secret File | `.p12` exported from Keychain Access |
| `ios-enterprise-cert-password` | Secret Text | Passphrase for the `.p12` |
| `ios-enterprise-provision-profile` | Secret File | `.mobileprovision` from Apple portal |

**How to export the `.p12` from Keychain Access:**
1. Open Keychain Access → My Certificates
2. Find `iPhone Distribution: YourBank Ltd (TEAMID)`
3. Right-click → Export → choose `.p12` format
4. Set a strong passphrase → save
5. Upload to Jenkins as a Secret File credential

### Creating the Jenkins job

1. New Item → Pipeline → name it `BankNow-iOS-Enterprise`
2. Definition: `Pipeline script from SCM`
3. SCM: Git → `file:///home/dk/Documents/git/testing-grounds` (or your remote URL)
4. Script Path: `jenkins-k8s/ios/option-4-enterprise/Jenkinsfile.groovy`
5. Lightweight checkout: ✓
6. Save → Build with Parameters

### Pipeline parameters explained

| Parameter | Default | Purpose |
|-----------|---------|---------|
| `ENVIRONMENT` | `Sit` | Selects scheme `BankNow_Sit/Uat/Prod` and env config |
| `AGENT` | `mobileapp` | Which Mac Mini to build on |
| `DUMMY_SIGNING` | `true` | `true` = dummy cert (no Apple account); `false` = real enterprise |
| `CERT_CREDENTIAL_ID` | `ios-enterprise-dist-cert-p12` | Jenkins credential ID for real `.p12` |
| `CERT_PASSWORD` | _(blank)_ | Real `.p12` passphrase — masked in console |
| `PROFILE_CREDENTIAL_ID` | `ios-enterprise-provision-profile` | Jenkins credential ID for real profile |
| `USE_PNPM` | `true` | `true` = pnpm; `false` = npm |
| `RUN_TESTS` | `true` | Run unit tests on simulator before archive |
| `CLEAN_BUILD` | `false` | Wipe DerivedData before archive (slower but fixes stale cache) |
| `NOTIFY_EMAIL` | _(blank)_ | Comma-separated email for build result |

## pnpm — Why and How

### Why pnpm over npm in CI

| Feature | npm | pnpm |
|---------|-----|------|
| Install speed (cold) | baseline | ~2–3× faster |
| Install speed (warm) | baseline | ~5× faster |
| Disk usage | copies packages | hard-links from content store |
| Phantom dependencies | allowed | blocked by default |
| `npm ci` equivalent | `npm ci` | `pnpm install --frozen-lockfile` |
| Parallel fetching | limited | yes |

pnpm stores every package version once in `~/.pnpm-store` and hard-links
into `node_modules`. On the second build, packages that haven't changed
are instant — no network, no copy.

### One-time migration from npm to pnpm

```bash
# 1. Install pnpm globally on each Mac Mini
npm install -g pnpm

# 2. Import existing package-lock.json into pnpm-lock.yaml
cd /path/to/your/react-native-project
pnpm import

# 3. Add React Native / Metro compatibility to .npmrc
#    Metro's resolver needs hoisted node_modules (not symlinked)
cat >> .npmrc << 'EOF'
node-linker=hoisted
shamefully-hoist=true
EOF

# 4. Test the install
pnpm install

# 5. Commit both files
git add pnpm-lock.yaml .npmrc
git commit -m "chore: migrate to pnpm for faster CI installs"
```

### What `node-linker=hoisted` does

Without it, pnpm creates a flat `node_modules/.pnpm/` structure with
symlinks. Metro bundler (React Native) cannot follow these symlinks reliably
and fails with "Unable to resolve module" errors. `node-linker=hoisted`
tells pnpm to hoist all packages into the top-level `node_modules/` the
same way npm does — Metro works without any other changes.

### Using pnpm in the Jenkinsfile

The pipeline checks `USE_PNPM` and calls the right tool:

```groovy
if (params.USE_PNPM) {
    // --frozen-lockfile = fail if pnpm-lock.yaml is out of date (like npm ci)
    // --prefer-offline  = use store cache; only hit network if missing
    pnpm install --frozen-lockfile --prefer-offline --reporter=append-only
} else {
    npm install --prefer-offline --no-audit --no-fund --no-progress
}
```

### pnpm store management on Mac Mini agents

The pnpm store (`~/.pnpm-store`) persists across builds automatically.
To save disk space on shared agents, you can configure a shared store:

```bash
# On each Mac Mini, add to ~/.zprofile or ~/.bash_profile:
export PNPM_HOME="/Users/shared/pnpm-store"
export PATH="$PNPM_HOME:$PATH"
pnpm config set store-dir /Users/shared/pnpm-store
```

Or let Jenkins manage it — the default per-user store is fine for most setups.

## Switching from Dummy to Real Signing

When your organisation provides the real Apple Developer Enterprise credentials:

### Step 1 — Upload credentials to Jenkins

```
Manage Jenkins → Credentials → System → Global credentials → Add Credential
```

Add three credentials:
1. **Secret File** → ID: `ios-enterprise-dist-cert-p12` → upload the `.p12`
2. **Secret Text** → ID: `ios-enterprise-cert-password` → the `.p12` passphrase
3. **Secret File** → ID: `ios-enterprise-provision-profile` → upload `.mobileprovision`

### Step 2 — Update ExportOptions-enterprise.plist

Edit `dummy-signing/ExportOptions-enterprise.plist` and replace:
- `REAL_TEAM_ID` → your Apple Team ID (10-character string, e.g. `ABCDE12345`)
- Profile name → the exact name shown in Apple Developer portal

```xml
<key>teamID</key>
<string>ABCDE12345</string>

<key>provisioningProfiles</key>
<dict>
    <key>com.yourbank.banknow</key>
    <string>YourBank Enterprise Distribution</string>
</dict>
```

Commit this file to the repo so Jenkins can read it.

### Step 3 — Run with real signing

Trigger the pipeline with `DUMMY_SIGNING = false`. Jenkins will:
1. Create a per-build ephemeral keychain
2. Import the real `.p12` from credentials
3. Install the real `.mobileprovision`
4. Run `xcodebuild archive`
5. Run `xcodebuild -exportArchive` with `ExportOptions-enterprise.plist`
6. Archive the real `.ipa` as a Jenkins artifact
7. Delete the ephemeral keychain in `post { always }`

## Troubleshooting

### `errSecInternalComponent` during codesign on Tahoe

**Cause:** macOS Tahoe (26) requires explicit codesign partition access.
The login keychain is locked under launchd-managed agents.

**Fix:** The script runs `security set-key-partition-list` automatically.
If it still fails, re-run `generate-dummy-signing.sh` → option 1.

```bash
# Manual fix if needed:
security set-key-partition-list \
    -S apple-tool:,apple:,codesign: \
    -s -k "your-keychain-password" \
    ios-banknow-dummy.keychain
```

### `errSecInteractionNotAllowed` — keychain locked

**Cause:** Keychain auto-locked (default timeout is 5 min; script sets 2h).

**Fix:** Unlock it, or re-generate:
```bash
security unlock-keychain -p "$(cat dummy-signing/.keychain_pass)" \
    ios-banknow-dummy.keychain
```

### Metro: `Unable to resolve module`

**Cause:** pnpm symlinked `node_modules` without hoisting.

**Fix:** Confirm `.npmrc` contains both lines:
```
node-linker=hoisted
shamefully-hoist=true
```
Then delete `node_modules/` and re-run `pnpm install`.

### `pod install` fails with unicode error

**Cause:** `LANG` not set; CocoaPods requires UTF-8 for unicode normalisation.

**Fix:** Already handled in the Jenkinsfile CocoaPods stage:
```bash
export LANG=en_US.UTF-8
```
Add this to `~/.zprofile` on the Mac Mini for interactive shells too.

### No `.app` found in `.xcarchive`

**Cause:** `xcodebuild archive` succeeded but used a wrong scheme or
the scheme has no archive action configured in Xcode.

**Fix:**
1. Open Xcode → Product → Scheme → Edit Scheme
2. Select Archive on the left
3. Ensure the correct target is selected and Build Configuration is `Release`
4. Confirm the scheme name matches `BankNow_Sit` (or whichever env)

### Provisioning profile expired warning in Jenkins

**Cause:** The `.mobileprovision` (dummy or real) has passed its expiry date.

**Fix for dummy:** Re-run `generate-dummy-signing.sh` → option 5 (clean) → option 1 (generate).
**Fix for real:** Renew the profile in Apple Developer portal and upload the new file to Jenkins credentials.
